# Mira

A voice conversation app with Firebase Authentication and optional private Google Drive histories, built with React and App Router. Vercel uses the installed Next.js framework; the original Vinext/Cloudflare Workers/D1 target remains available. See `DEPLOY-VERCEL.md` for GitHub deployment, server environment variables, Firebase Spark and Google OAuth settings, and checks. It supports Gemini Live over WebSockets and OpenAI Realtime over WebRTC.

## Use

Open the link, sign in or create an account, and choose Start talking. Email/password and Google sign-in use the supplied Firebase project, `mira-speaking-partner`. The app uses Gemini Live with a server secret. The browser receives only a short-lived, single-session token restricted to the voice configuration. Voice-provider keys remain on the server.

Configure `GEMINI_API_KEY` as a server secret; `GEMINI_LIVE_MODEL` defaults to `gemini-3.8-live`. The 2.5 model remains supported as an explicit override. Alternatively configure `OPENAI_API_KEY` with `OPENAI_REALTIME_MODEL` (default `gpt-realtime-2.1`). Gemini takes priority when both are configured. When no server provider is configured, Settings accepts a personal OpenAI key in page memory only. Refreshing forgets it. API use is charged to the configured account. `.env.example` lists settings without secret values.

For the local preview, keep credentials in ignored `.env.local`; the Cloudflare runtime loads them on the server. Visitors can choose Start talking without entering a key. With Gemini, set `WHISPER_API_STYLE=openai`, `WHISPER_MODEL=whisper-1`, and `WHISPER_API_KEY` to an OpenAI key for OpenAI-hosted speech transcription; no Whisper server URL is needed. Hosted deployments need the same values configured separately as server secrets and variables.

Set `WHISPER_ENABLED=false` to use Gemini's native speech recognition when Whisper is unavailable. Set it to `true` after restoring transcription access and API credits; visitors still do not need to enter keys.

Choose Start talking, review the microphone notice, and allow the browser’s permission request. Text input can start a session without microphone permission. End conversation closes the peer connection, stops microphone tracks, and closes the audio context. Calls end after 30 minutes.

## Conversation behavior

- When Whisper is configured, the voice path is microphone → Whisper → text → Gemini Live → avatar audio. `openai` mode sends short recordings to OpenAI-hosted Whisper using the server-only `WHISPER_API_KEY`. The `speaches` and `raw` modes use a separate faster-whisper server and its own token. Recordings stay in memory while being transcribed; their recognized text appears in the chat. See `services/whisper/README.md` for both configurations.
- Whisper mode segments speech on a short pause and shows a transcription status. Starting to speak stops queued avatar playback; stale reply audio stays discarded while the next recognized turn is prepared. Transcript latency depends on the server and recording length.
- Native Gemini mode streams 20 ms microphone chunks and displays partial transcripts as they arrive. Automatic speech detection remains enabled; a client-side end-of-speech signal flushes audio after a 500 ms pause (1 second for “Give me more time”). The local Silero v5 speech detector stops queued playback on sustained speech without waiting for a network round trip, while microphone audio continues streaming. Stale output is discarded until cancellation is acknowledged, and cancellation boundaries preserve the new user turn. A lightweight detector and server VAD remain available if the neural detector cannot load. Provider, microphone acoustics, and network latency still affect timing. The default Gemini voice is Sulafat, with soft, warm feminine delivery.
- Whisper mode uses a 450 ms normal end-of-speech pause and Gemini with thinking disabled. Self-hosted Speaches defaults to multilingual Whisper base; OpenAI-hosted mode defaults to `whisper-1`. Explicit activity signals cancel Gemini generation while the next utterance is being transcribed, instead of waiting for the old reply to finish. “Give me more time” retains its 1.1-second pause.

- Gemini uses an AudioWorklet to capture mono 16 kHz PCM, streams directly over a token-authenticated WebSocket, and schedules streamed PCM responses for playback. Local speech detection and Gemini's interruption events stop queued audio. Echo cancellation remains enabled during playback. Session resumption handles planned connection renewals. OpenAI uses WebRTC and a server-side SDP handshake.
- `scripts/run-framework.mjs` copies the pinned VAD package's model, worklet, and ONNX runtime assets into ignored `public/vad/` before dev/build. They are served from the app origin and loaded in parallel with connection setup. VAD processes the existing microphone locally; it does not create another permission request or send audio to an additional service. The approximately 14 MB WASM runtime and 2 MB model are cacheable after the first download.
- Semantic voice activity detection supports natural pauses and automatic interruption. WebRTC’s server output buffer cancels and truncates unplayed audio. Text interruptions wait for cancellation before starting a replacement response.
- Echo cancellation, automatic gain control, browser noise suppression, and optional browser voice isolation help with noise. Gemini uses speech detection sensitivity appropriate to the microphone; OpenAI additionally uses server near/far-field reduction. This is not speaker authentication and cannot reliably exclude all nearby speakers.
- Mira uses a 3D avatar with audio-driven lip sync and a live waveform. Loading and error states show a status message rather than a 2D portrait; the 3D model is preloaded and its renderer is capped for tablet performance.
- Both speakers’ transcripts stream into chat. New transcripts save only to the signed-in person’s connected Google Drive folder after a call ends, automatically when enabled or through the manual save button. Without Drive, text remains on screen only. New D1 transcript writes are disabled; old records remain intact. Audio recordings are not retained by this app. The selected provider processes audio under that API account’s applicable data terms; microphone consent names that provider.
- Transcriptions are an approximate record. An interrupted output is labeled because text can arrive before its audio is heard.
- Drive history supports viewing, downloading, and moving conversations to recoverable Drive Trash. Optional Drive authorization requests only `drive.file`, verifies the Google email matches Firebase, and keeps tokens in page memory. Settings includes private folder creation, automatic-save preference, reconnection, and disconnect. Monotonic revisions prevent delayed autosaves from overwriting newer text. Failed saves remain in memory, visibly offer retry/export, and warn before closing the page. Unsent data cannot survive browser termination.

## Development

Run `npm run install:ci`, then `npm run dev`. The development URL is printed by Vinext. Firebase persists authentication in IndexedDB with localStorage fallback until explicit sign-out. The frontend passes refreshed Firebase ID tokens to protected app APIs, and Workers verifies their RS256 signature, issuer, audience, expiry, subject, and authentication time using Google's public keys. No Admin SDK private key is needed. Logout ends audio and attempts enabled Drive saving before signing out. If unsaved text remains, users must keep it or explicitly confirm discarding it; Drive is never required to use Mira.

Authentication modules live in `lib/auth/` and `components/auth/`, with `/sign-in`, `/sign-up`, and `/forgot-password` pages. `lib/auth/firebase-config.ts` contains the supplied public Firebase web configuration. Analytics is optional and is not initialized by the authentication integration. Google sign-in uses a popup to avoid cross-origin redirect-storage restrictions on the temporary preview host; browsers must allow that popup.

Google's popup resolver initializes only when Google is selected, so its cross-origin iframe and authorized-domain requirements do not interfere with email sign-in or startup. Registration completes and reloads the profile name before opening the app. If Firebase creates the account before a subsequent network request fails, registration recovers using the same credentials instead of registering again. Network retries are bounded; invalid credentials and duplicate-account errors remain explicit.

Existing stored rows and the database schema are preserved. `/api/config` retains the existing HttpOnly browser cookie. After verified login, `/api/auth/session` attaches only that cookie's legacy anonymous conversations to the first Firebase account that claims them, preserving IDs, contents, revisions, and dates. A second account cannot reclaim them. Those preserved records stay scoped to the Firebase account in the existing D1 runtime; they are not silently transferred to a different hosting service. New history comes from the user’s selected Drive folder after reconnection. Other legacy ownership records remain unchanged and private. The first login must happen on the same origin/browser that still holds the old cookie; a changed temporary tunnel hostname cannot access the old origin's cookie.

In Firebase Console → Authentication → Sign-in method, enable Email/Password and Google (including its support email). In Authentication → Settings → Authorized domains, add each deployed/preview hostname, without `https://` or a path. As of the implementation checks, both provider endpoints respond successfully; the new temporary preview hostname `shorter-ons-relates-resources.trycloudflare.com` still needs authorization for Google. A new quick tunnel may use a different hostname. `localhost` is already authorized. Password-reset messages use Firebase's hosted action handler and email templates.

Generate database migrations with `npm run db:generate`. Build with `npm run build`, then apply the generated migration locally using the starter’s documented Wrangler command in `README.md`. Sites applies migrations during deployment.

Run `node --test tests/*.test.mjs` and `node node_modules/typescript/bin/tsc --noEmit` for local validation. Build Firebase production with `node scripts/build-firebase.mjs`. For opt-in real Firebase/Gemini checks, set `MIRA_AUTH_INTEGRATION=1` and `MIRA_BASE_URL` to the production backend or published HTTPS origin, then run `node tests/firebase-production.integration.mjs`. This creates and removes only disposable synthetic accounts and verifies that new server transcript storage is disabled. The existing `tests/auth.integration.mjs` and `tests/api.integration.mjs` entry points route to these production checks under the new Drive-only policy.

Earlier browser checks (before the Drive changes) confirmed fresh signup with a saved display name, existing-account sign-in, reload persistence, logout after saving a live conversation, history on returning, password visibility, invalid-password feedback, password-reset success, and mobile/tablet layouts. Google reports the expected unauthorized-domain message until the final preview hostname is added; completing Google OAuth requires that setting and the user's Google account.
